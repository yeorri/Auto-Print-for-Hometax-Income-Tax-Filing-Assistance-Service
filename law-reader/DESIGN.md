# 법조문 뷰어 (가칭: 조문나무 / law-reader) — 설계 문서

> 목표: 법조문을 읽을 때 "대통령령으로 정한다" 같은 위임 조항이나 상호참조를
> 새 창으로 타고 들어가지 않고, **한 화면에서 트리/임베드로 연결지어 읽게** 하는
> 데스크탑(우선 웹) 앱.

---

## 1. 우리가 푸는 진짜 문제

법령 읽기의 피로는 "텍스트가 어려워서"가 아니라 **구조가 흩어져 있어서**입니다.

| 현재 (law.go.kr 등) | 우리가 만들 것 |
|---|---|
| "~는 대통령령으로 정한다" → 시행령 어디인지 안 알려줌 | 해당 위임을 받은 시행령 조문을 **그 자리에 임베드** |
| 참조 링크가 새 창에서 열림 | **같은 화면 분할 / 팝오버 / 핀(pin)** 으로 옆에 고정 |
| 법·시행령·시행규칙이 따로따로 | **체계도 트리**로 한눈에, 클릭하면 본문 이동 |
| 타고 들어가다 원래 보던 곳을 잊음 | **읽기 스택 + 탭 + 브레드크럼**으로 컨텍스트 보존 |

## 2. 핵심 통찰 (이 프로젝트의 성패를 가르는 3가지)

### 통찰 1 — 데이터는 직접 크롤링하지 말고 공식 OPEN API를 쓴다
**국가법령정보 공동활용 OPEN API** (https://open.law.go.kr) 가
법령 본문을 `조-항-호-목` 단위로 구조화해서 XML/JSON으로 줍니다.
- 인증키(OC)는 이메일 아이디 기반으로 무료 발급 (`open.law.go.kr` 가입 → 활용신청).
- 주요 엔드포인트 (DRF):
  - 법령 검색: `lawSearch.do?OC={key}&target=law&query={검색어}&type=JSON`
  - 법령 본문: `lawService.do?OC={key}&target=law&MST={법령일련번호}&type=JSON`
  - **법령 체계도**: `target=lsStmd` → 법 ↔ 시행령 ↔ 시행규칙 트리
  - 위임행정규칙 / 별표·서식 / 신구법 비교 등 부가 데이터도 제공
- 참고용 선행 프로젝트: `chrisryugj/korean-law-mcp` (법제처 42개 API를 정리해 둠) — 엔드포인트 레퍼런스로 유용.

### 통찰 2 — "대통령령으로 정한다 ↔ 시행령 어느 조문" 매핑이 핵심 난제
법조문에는 "대통령령으로 정한다"라고만 있고 **시행령 몇 조인지는 안 적혀 있습니다.**
이걸 잇는 게 이 앱의 가장 큰 가치이자 가장 어려운 부분. 2단계로 푼다:

1. **(우선) 역참조 인덱싱** — 시행령/시행규칙 조문은 거의 항상
   본문에 `법 제15조제2항에 따라…`, `영 제3조…` 처럼 **모법 조문을 역으로 인용**한다.
   → 시행령 전체를 파싱해 "이 시행령 조문은 모법 제N조를 가리킨다"는 **역인덱스**를 만들면,
     모법 제N조를 볼 때 "이 조문을 인용하는 하위법령 조문들"을 자동으로 모아 임베드할 수 있다.
   → API 의존 없이도 동작하는 가장 견고한 방법.
2. **(보강) API 위임연계 데이터** — 공동활용 API의 위임행정규칙/연계 목록을 합쳐 정확도를 높인다.

### 통찰 3 — 웹앱은 CORS 벽에 막힌다 → API 호출을 추상화해 둔다
law.go.kr DRF API는 브라우저 CORS 헤더를 안 주고 IP 제한이 있을 수 있어
**브라우저에서 직접 fetch하면 실패**한다.
- 개발: Vite dev proxy (`/law-api` → `www.law.go.kr`) 로 우회.
- 배포(웹): 얇은 프록시(서버리스 함수/Express) 1개.
- **나중에 Tauri/Electron으로 전환하면** 네이티브 HTTP 계층이 CORS를 안 타므로 프록시 불필요.
- 그래서 `LawApiClient` 인터페이스로 추상화 → 프록시 ↔ 네이티브 구현 교체가 한 줄.

## 4. 참조 탐지 규칙 (crossref)

본문 텍스트에서 정규식으로 다음 토큰을 찾아 클릭 가능한 span으로 변환:

| 종류 | 예시 | 처리 |
|---|---|---|
| 위임 (delegation) | "대통령령으로 정한다", "총리령으로 정하는", "○○부령으로" | 역인덱스로 하위법령 조문 임베드 |
| 내부참조 (internal) | "제15조", "제2항", "제3호", "제15조의2" | 같은 법령 내 점프 |
| 별표·서식 (appendix) | "별표 제1호", "별지 제3호서식" | 별표 뷰어로 |
| 타법참조 (external) | "「소득세법」 제12조" | 다른 법령 로드 후 점프 |

⚠️ 한국 법령 번호 특성: `제15조의2`(가지조), `제15조제2항제3호` 연속 표기,
한글/아라비아 혼용 → 파서에서 정규화 필요.

## 5. 단계별 로드맵

- **Phase 0 (현재) — 골격 + 설계**: 폴더 구조, 타입, 인터페이스 스텁, 본 문서.
- **Phase 1 — 본문 렌더**: OC키 연동 → 법령 검색 → 조-항-호-목 트리 렌더 + 체계도 트리.
- **Phase 2 — 참조 미리보기**: 참조어 하이라이트 → 클릭 시 팝오버/핀 미리보기 (새 창 X).
- **Phase 3 — 위임 임베드**: 역인덱스 구축 → "대통령령으로 정한다" 자리에 시행령 조문 아코디언.
- **Phase 4 — 데스크탑화 + 오프라인**: Tauri/Electron 포장, SQLite 캐시, 즐겨찾기/메모.

각 Phase 끝에서 동작 확인 후 커밋.

## 7. 이 폴더를 새 저장소로 분리하는 법

지금은 홈택스 저장소의 한 브랜치 안에 들어있다. 새 repo로 옮기려면:

```bash
# 1) 새 폴더로 복사
cp -r law-reader ~/law-reader && cd ~/law-reader
# 2) 독립 git 저장소로 초기화
git init && git add . && git commit -m "init: 법조문 뷰어 골격"
# 3) GitHub에서 새 repo 생성 후 연결
git remote add origin https://github.com/<당신아이디>/law-reader.git
git push -u origin main
```
